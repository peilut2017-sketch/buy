# מבנה הנתונים

הסכמה המלאה: `supabase/migrations/0001_init.sql`. זו טיוטה שנבדקה תחבירית בלבד, וצריך לעבור עליה מול האפיון לפני שמריצים.

## כללים שהסכמה אוכפת

- **ביקורת אחת לכל משתמש לכל דגם אב** (`unique (user_id, product_id)`). שינויים הם עריכה או עדכון.
- **הזמנה אחת ננעלת לחשבון אחד** (`unique (site_id, order_hash)`).
- **דיווח אחד לביקורת למשתמש, ערעור אחד לביקורת.**
- **טקסט ביקורת 30 עד 2,000 תווים.** ביקורת בלי טקסט היא דירוג מהיר שלא מתפרסם.
- **שלב הביקורת** (התרשמות ראשונה, אחרי שימוש, שימוש ממושך) מחושב בפונקציה `review_stage`.
- **`product_summary`** היא תצוגה שמזינה את הפס והפאנל. כשהנפח יגדל, להחליף לתצוגה ממומשת שמתרעננת.

## הרשאות (RLS)

- **קריאה ציבורית:** אתרים פעילים, מוצרים, וריאנטים, ביקורות גלויות ועדכונים שלהן, מחירים, שאלות, מוני מדרגים.
- **נתונים אישיים:** כל משתמש רואה ומשנה רק את שלו.
- **כתיבות רגישות** (ביקורות, דיווחים, ערעורים, הזמנות, מחירים, אירועים, התראות) רק דרך Edge Functions עם מפתח השירות, שבודקות קלט, מגבילות קצב ורושמות ביומן.
- **לפני ההשקה:** לחשוף מ-`profiles` רק את הכינוי, דרך תצוגה או הרשאות עמודה. כרגע המדיניות פותחת את כל השורה לקריאה.
